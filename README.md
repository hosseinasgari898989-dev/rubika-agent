# Rubika-Agent — Cloud + Python Brain

هدف مخزن، اجرای امن و تا حد ممکن کم‌هزینهٔ دستیار کانال Poppy Playtime است. مسیر عادی جمع‌آوری به اجرای دستی روی گوشی وابسته نیست.

## مسیر فعال جمع‌آوری

- گردش کار `.github/workflows/termux-docker-discovery.yml` در GitHub Actions هر ساعت دو بار گیت زمان‌بندی را بررسی می‌کند. جمع‌آوری کامل وقتی شروع می‌شود که پنج ساعت از آخرین intake موفق به D1 گذشته باشد.
- این workflow تصویر Termux Docker را داخل runner ابری اجرا می‌کند؛ **Termux روی گوشی لازم نیست**. اسکریپت‌های مخصوص راه‌اندازی و اجرای روزانه روی گوشی حذف شده‌اند.
- منبع ادیت TikTok فقط شش پروفایل سازندهٔ انتخاب‌شده در تنظیمات پروژه است. خبر رسمی Mob Entertainment فقط از X و حساب رسمی پیکربندی‌شده جمع‌آوری می‌شود.
- collector فقط metadata می‌گیرد: رسانه دانلود نمی‌شود و این workflow در روبیکا چیزی منتشر نمی‌کند. گزارش معتبر در `artifacts/termux_discovery.json` ذخیره می‌شود؛ سپس intake حداکثر چهار URL جدید را پس از فیلتر و حذف تکراری‌ها به صف پایدار D1 اضافه می‌کند.
- راهنمای جزئیات اجرا و عیب‌یابی در [docs/CLOUD_DISCOVERY.md](docs/CLOUD_DISCOVERY.md) است.

## پردازش صف و انتشار

گردش کار جمع‌آوری از پردازش صف جداست. `.github/workflows/daily-queue-processor.yml` صف D1 را با سقف چهار انتشار موفق روزانه پردازش می‌کند؛ این مسیر می‌تواند رسانه دانلود کند و در مقصد تعیین‌شده منتشر کند، پس گیت‌هایش با collector یکی نیستند. برای آزمون دستی چهار ویدئویی، workflow تأیید صریح دارد و به کانال آزمایشی ثابت محدود است.

خبرهای رسمی Mob نیز مسیر جداگانه دارند. تنظیمات lifecycle فعلی از مرز زمانی `2026-10-20T00:00:00Z` استفاده می‌کند و برای خبر رسمی فقط X فعال است. هرچند پیکربندی خبر در حالت production است، مقصد پیکربندی‌شده و workflow خبر هنوز به شناسهٔ کانال آزمایشی قفل‌اند؛ این به معنی فعال بودن کانال اصلی نیست.

آزمایش‌های سرتاسریِ دانلود رسانه و انتشار واقعی فقط از مسیرهای دستی و دارای مجوز جداگانه‌اند. راهنما در [docs/END_TO_END_SMOKE.md](docs/END_TO_END_SMOKE.md) قرار دارد. صرف موفقیت CI یا جمع‌آوری metadata اثبات ارسال واقعی نیست.

## نقش اجزا

- **Python brain:** فیلتر منبع و محتوا، تشخیص تکراری‌ها، اعتبارسنجی رسانه، صف‌بندی و مدیریت وضعیت ارسال.
- **Cloudflare Worker + D1:** API کنترل، metadata، صف و تاریخچهٔ پایدار.
- **Workers AI:** فقط برای تشخیص موسیقی از صدای ویدیو با Clef Omni؛ نتیجهٔ نامطمئن نیازمند بازبینی انسانی است. این سرویس برای تعمیر کد یا ترجمه استفاده نمی‌شود.
- **Groq و OpenRouter Free:** ترجمهٔ خبر رسمی و تشخیص/پیشنهاد/بازبینی محدود برای تعمیر کد. هر درخواست باید در D1 رزرو و ثبت نتیجه شود. تعمیر خودکار merge نمی‌کند؛ بعد از تست‌ها فقط PR برای بازبینی انسانی می‌سازد.
- **GitHub Actions:** تست‌ها، جمع‌آوری ابری، نگه‌داری صف و اجرای jobهای محدود. runner دائمی نیست.

## قوانین مهم

- Tokenها و API keyها فقط در GitHub Secrets/Cloudflare Secrets نگه‌داری می‌شوند؛ هیچ مقدار محرمانه‌ای نباید در فایل یا لاگ چاپ شود.
- جمع‌آوری metadata به معنی مجاز بودن بازنشر، دانلود موفق یا انتشار نیست؛ هر مرحله gate جداگانه دارد.
- مقصد فعلی روبیکا برای آزمایش به شناسهٔ کانال تست متصل است. Secret مقصد را برای «درست شدن تست» به کانال اصلی تغییر نده.
- Migration از راه دور D1 جدا از Worker deploy است و نباید بدون بررسی و تأیید اجرا شود.
- تغییرات مربوط به کانال اصلی باید در یک تغییر جداگانه، با GUID تأییدشده، preflight فقط‌خواندنی و گیت تولید مستقل انجام شوند.
