# Rubika-Agent — Cloud + Python Brain

هدف این مخزن ساخت دستیار ماژولار برای کانال @poppy_play_time_HV است. پروژه باید تا حد ممکن رایگان بماند، اما هیچ سرویس یا سهمیه‌ای را نامحدود فرض نمی‌کنیم.

- Cloudflare Worker: rubika-agent
- Worker URL: https://rubika-agent.h98609294.workers.dev
- Health: /health
- Status: /api/status
- Cloudflare D1: rubika-agent-db
- مخزن GitHub: hosseinasgari898989-dev/rubika-agent
- MEGA: پوشه اختصاصی Rubika-Agent در حساب صاحب پروژه

آزمایش واقعی MEGA در GitHub Actions ورود امن، دسترسی پوشه، آپلود و دانلود فایل کوچک و تطابق SHA-256 را تأیید کرده است. فایل آزمایشی پس از بررسی حذف شد. این نتیجه، اتصال آزمایشی را ثابت می‌کند، نه آرشیو یا اتصال کامل همهٔ فایل‌های رسانه‌ای.

## وظایف اصلی
- Python: تصمیم‌گیری، بررسی فایل، تشخیص تکراری‌ها، سیاست محتوا، آماده‌سازی دسته و مدیریت تلاش‌های ارسال.
- Cloudflare Worker + D1: API کنترل و حافظهٔ فراداده‌ها/تاریخچه.
- MEGAcmd: آپلود، دانلود و حذف امن فایل‌های مرحلهٔ آماده‌سازی.
- GitHub Actions: تست خودکار و اجرای کارهای موقت؛ runner دائمی نیست.
- Cobalt: دریافت رسانه از پلتفرم‌هایی که برای لینک عمومی مشخص پشتیبانی می‌شوند.
- Rubka 8.1.7: ارتباط با روبیکا؛ روش‌های تأییدشده در محیط قبلی sync بوده‌اند و پاسخ‌های JSON باید بررسی شوند.

## مغز Python
مشخصات ماژول‌ها در docs/AGENT_BRAIN_V1.md آمده است. دو مسیر محتوا از هم جدا هستند:
1. ادیت‌های Poppy Playtime از TikTok، YouTube و Instagram، با بررسی تکراری‌بودن، وضوح، قالب مربع، آهنگ و تصمیم‌های محتوایی.
2. رسانه‌های رسمی Mob Entertainment شامل ویدیو، عکس و صدا؛ کپشن اصلی و ترجمه فقط وقتی در دسترس باشند قالب‌بندی می‌شوند.

فهرست منابع قابل‌اعتماد در config/trusted_sources.json عمداً خالی است تا صاحب پروژه منابعش را انتخاب کند.

## محدودیت‌های فعلی
- شاخه agent-brain-mega-v1 یک شاخهٔ آزمایشی است؛ هنوز با main ادغام نشده و Worker تولیدی را تغییر نمی‌دهد.
- موتور جست‌وجوی TikTok که قبلاً کار می‌کرد هنوز به نسخهٔ جدید بازسازی نشده است.
- YouTube Data API اطلاعات ویدیو می‌دهد و خودش فایل MP4 تحویل نمی‌دهد. دانلود یوتیوب در Termux باید از همان روش قبلی که موفق بوده استفاده کند؛ محدودیت‌های ورود و دسترسی را دور نمی‌زنیم.
- ارزیابی تصویری/شنیداری واقعی برای تشخیص ادیت سطح بالا، توهین‌ها و وجود موسیقی به یک طبقه‌بند واقعی نیاز دارد. تا پیش از اتصال و آزمون آن، مغز نباید نامطمئن‌ها را خودکار تأیید کند.
- Migrationهای جدید D1 باید جداگانه و آگاهانه روی دیتابیس remote اعمال شوند؛ deploy معمولی Worker لزوماً migration را اجرا نمی‌کند.
- ارسال خودکار فقط پس از آماده‌بودن کل دسته انجام می‌شود. پاسخ مبهم روبیکا به معنی «نامشخص» است، نه شکست قطعی؛ در این حالت ارسال دوباره انجام نمی‌شود تا پست تکراری ساخته نشود.
- فایل محلی و MEGA فقط پس از تأیید صریح status=OK برای ارسال پاک می‌شوند. اطلاعات متنی/هش/تاریخچه باید باقی بمانند.
