## ساختار ریپو

- `.github/workflows/`: گردش‌کارهای GitHub Actions برای CI، صف، پردازش رسانه، آزمون کنسول، استقرار Worker، AI و بررسی‌های عملیاتی.
- `src/`: کد Cloudflare Worker؛ ورودی درخواست‌ها، پنل مالک، API کنسول و مسیرهای کنترل.
- `migrations/`: مایگریشن‌های D1؛ فقط برای بررسی و استقرار کنترل‌شده.
- `agent/brain/`: منطق پایتون عامل، پردازش Mob X، وضعیت ابری و ترجمه.
- `agent/storage/`: ذخیره‌سازی رسانه، از جمله اتصال MEGA.
- `scripts/`: ابزارهای پردازش، پیش‌بررسی صف و زیرنویس.
- `tests/`: تست‌های واحد، قرارداد API و آزمون‌های mock.
- `assets/`: منابع موردنیاز پردازش رسانه/زیرنویس، از جمله فونت‌های مورد استفاده.
- `config/`: محدودیت‌های کنترل‌شدهٔ ترجمه و پردازش.
- `docs/`: راهنماها و این سند تحویل.
- `termux/` و `relay/`: اجزای مربوط به اجرا و انتقال، طبق فایل‌های موجود در snapshot.
- `artifacts/`: خروجی‌های قابل ردیابی که در ریپو نگه‌داری شده‌اند.
- `vendor/rubka-library.zip`: ZIP مستقل کتابخانهٔ نصب‌شدهٔ `rubka==8.1.7`؛ این فایل داخل Artifact تولید می‌شود.

## معماری و اتصال سرویس‌ها

1. **Cloudflare Worker**: نقطهٔ کنترل/API برای پنل و پردازش؛ endpointهای موجود در `src/index.js` و `src/console_api.js` مسیرهای صف و وضعیت را مدیریت می‌کنند.
2. **D1**: پایگاه دادهٔ Worker با binding تعریف‌شده در `wrangler.jsonc`؛ وضعیت صف، لینک‌های پنل و دفتر ثبت مصرف AI در آن نگه‌داری می‌شوند.
3. **GitHub Actions**: اجراهای زمان‌بندی‌شده و CI کارهای سنگین پایتون را انجام می‌دهند؛ فایل‌های workflow مشخص می‌کنند هر کار از چه Secret/Variableهایی استفاده می‌کند.
4. **MEGA**: ذخیره‌سازی رسانهٔ موقت/آمادهٔ بررسی از طریق `agent/storage/mega.py` و ابزار رسمی MEGAcmd در workflowهای مربوط.
5. **Mob X**: لینک تأییدشده بررسی می‌شود؛ هویت حساب و شناسهٔ پست اعتبارسنجی شده، رسانه دریافت و اعتبارسنجی می‌شود، در صورت نیاز گفتار/زیرنویس پردازش و ترجمه انجام می‌شود و پیش‌نمایش برای مالک ارسال می‌شود.
6. **زنجیرهٔ ترجمه**: `Groq → OpenRouter → Worker AI`. دفتر مصرف و سقف‌های داخلی مجزا از شمارندهٔ Neurons حساب هستند؛ مصرف پایین Neurons به‌تنهایی سلامت این سه مسیر را اثبات نمی‌کند.
7. **انتشار**: پردازشگر لینک به‌تنهایی انتشار کانال را انجام نمی‌دهد. ناشر جداگانه و کنترل gate/مقصد تست اعمال می‌کند. قفل کانال اصلی و gate موجود نباید دستکاری شوند.

## باگ‌ها و ریسک‌های شناخته‌شده

- **Mob X، سقف رسانه**: در اجرای `40640482002` خطای `mob_x_video_too_large` ثبت شد. کد فعلی سقف دانلود/بازبینی را `100 MiB` تنظیم می‌کند؛ لاگ موجود حجم دقیق فایل را ثبت نکرده است. سقف عمداً در این کار تغییر داده نمی‌شود.
- **Mob X، timeout پیش‌بررسی صف**: PR #120 فیلتر سمت Worker و تلاش مجدد محدود را اضافه کرد (حداکثر ۳ تلاش و backoff کوتاه؛ timeout درخواست/بدنه ۲۰ ثانیه). اجرای اخیر از مرحلهٔ preflight عبور کرده و بعداً به خطای حجم رسانه رسیده بود؛ timeout همچنان باید در اجراهای بعدی پایش شود.
- **خطای ترجمهٔ کلی**: `mob_x_translation_failed` می‌تواند به معنی سهمیهٔ داخلی/سرویس، محدودیت ارائه‌دهنده، پاسخ خالی، متن نامعتبر یا شماره‌گذاری نامنطبق زیرنویس باشد. تابع زنجیرهٔ ترجمه در برخی مسیرها علت اصلی را به `None` تبدیل می‌کند؛ بنابراین هشدار فعلی به‌تنهایی اثبات نمی‌کند که سهمیه تمام شده است. نیاز باز: ثبت علت نهایی هر ارائه‌دهنده به‌شکل امن (کد خطا/HTTP status/finish reason) بدون خروجی خام یا Secret.
- **بودجه‌ها مستقل‌اند**: سقف داخلی ترجمه در Worker و ledger، سهمیه/محدودیت Groq، OpenRouter و شمارندهٔ Neurons هرکدام جدا هستند. عدد Neurons به‌تنهایی وضعیت ledger یا API key را تعیین نمی‌کند.
- **ترجمهٔ زیرنویس fail-closed است**: اگر یکی از batchها ترجمه نشود یا شماره cueها/جداکننده‌ها مطابق ورودی نباشد، زیرنویس ناقص ساخته یا منتشر نمی‌شود؛ این رفتار حفاظتی است.
- **اطلاعات اندازهٔ واقعی رسانه**: لازم است error report در حد مجاز، اندازهٔ اعلامی/دریافت‌شده را بدون URL یا credential ثبت کند.
- **استقرار و مقصد انتشار**: Secretها، gate و مقصد کانال تست را برای عیب‌یابی تغییر ندهید. کانال اصلی قفل است؛ هیچ انتشار واقعی از این بسته انجام نمی‌شود.
- **Migration 0011**: طبق تأیید مالک قبلاً روی D1 اجرا و بررسی شده است؛ آن را دوباره اجرا نکنید.

## آزمون‌ها و ایمنی بسته

- بسته‌سازی از snapshot جاری `main` انجام می‌شود؛ تاریخچهٔ Git و پوشه‌های موقت/وابستگی‌های نصب‌شده وارد نمی‌شوند.
- همهٔ فایل‌های `.env*`، `.dev.vars`، مخزن Git، cacheها، کلیدهای خصوصی و فایل‌های محلی دیتابیس از خروجی حذف می‌شوند.
- متن فایل‌ها برای کلیدهای قابل‌شناسایی و مقدارهایی که به نام Secret/GUID تخصیص یافته‌اند اسکن و در صورت لزوم redacted می‌شود؛ اگر الگوی پرخطر باقی بماند، ساخت متوقف می‌شود.
- تاریخچهٔ workflowها به‌شکل **خلاصهٔ امن** (زمان، event، نتیجه، job/step شکست‌خورده و لینک اجرا) ذخیره می‌شود، نه متن خام لاگ‌ها؛ این کار احتمال نشت مقادیر پنهان‌شده در لاگ را کاهش می‌دهد.
