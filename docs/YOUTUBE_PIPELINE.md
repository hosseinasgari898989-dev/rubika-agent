# مسیر پردازش یوتیوب

این فاز جدا از صف انتشار فعلی ساخته می‌شود. ماژول فعلی فقط سیاست و فرمان‌های قابل‌آزمایش را می‌سازد؛ هیچ دانلود، رونویسی، ترجمه، آپلود روبیکا یا انتشار واقعی انجام نمی‌دهد.

## قانون ثابت خروجی: 720p

هر ویدیوی خروجی باید پس از پردازش با ffmpeg به MP4 استاندارد تبدیل شود و از سقف ابعاد 720p عبور نکند:

- افقی: حداکثر 1280×720
- عمودی/Short: حداکثر 720×1280
- مربعی: حداکثر 720×720
- نسبت تصویر حفظ می‌شود و ویدیوی کم‌وضوح بی‌دلیل بزرگ‌نمایی نمی‌شود.
- yt-dlp هنگام دریافت، فرمت سازگار با ابعاد منبع را انتخاب می‌کند؛ ffmpeg مرحلهٔ نهاییِ تضمین‌کنندهٔ سقف ابعاد است. خروجی نهایی باید با ffprobe دوباره بررسی شود؛ انتخاب فرمت دانلود به‌تنهایی کافی نیست.

## دانلود فایل‌های بزرگ

- آستانهٔ «بزرگ» 700,000,000 بایت است؛ این سقف دانلود نیست. فایل 700 مگابایت یا 1 گیگابایت به‌خودی‌خود رد نمی‌شود.
- برای رسانهٔ بزرگ، دانلودهای HTTP گزینهٔ chunk ده مگابایتی می‌گیرند؛ دریافت ناقص قابل ادامه است و retryها/fragmentهای هم‌زمان محدودند. chunk اندازهٔ کل فایل را کم نمی‌کند و برای DASH/HLS قطعه‌بندی از قبل توسط جریان رسانه مدیریت می‌شود.
- قبل از دانلود، اندازهٔ تخمینی رسانه و فضای خالی runner بررسی می‌شود. برآورد محافظه‌کارانه حداقل 2.2 برابر حجم منبع به‌علاوهٔ 2 GiB فضای آزاد نگه می‌دارد تا فایل ورودی، خروجی تبدیل و فایل‌های موقت هم‌زمان جا شوند. اگر اندازه یا فضای خالی معلوم نباشد، برنامه اجازهٔ دانلود امن نمی‌دهد.
- پس از تبدیل، اندازهٔ فایل خروجی جداگانه کنترل می‌شود؛ اندازهٔ فایل منبع، خروجی 720p را پیش‌بینی قطعی نمی‌کند.

## محدودیت آپلود روبیکا

در اسناد عمومی‌ای که بررسی شد، عدد رسمی و صریحی برای بیشینهٔ حجم کل فایل ویدیویی قابل آپلود از Bot API پیدا نشد. مستندات عمومی Rubka وجود متدهای get_upload_url و upload_media_file را توضیح می‌دهد، اما حد عددی کل فایل را مشخص نمی‌کند. یک منبع ثالث عدد 50 MB را ادعا می‌کند، ولی رسمی نیست و نباید بدون آزمایش معادل سقف قطعی API فرض شود.

بنابراین rubika_upload_limit_bytes عمداً null است. تا زمانی که سقف واقعی در یک آزمایش کنترل‌شدهٔ کانال تست تأیید نشود، کنترل اندازه وضعیت rubika_upload_limit_unverified می‌دهد و آپلود را رد می‌کند. پس از ثبت سقف تأییدشده در تنظیمات، 10٪ حاشیهٔ اطمینان هم اعمال می‌شود. این PR هیچ آپلودی انجام نمی‌دهد و هیچ پیامی به روبیکا نمی‌فرستد.

## کانال‌ها و زیرنویس فارسی

- انتخاب کانال‌ها از منابع youtube با enabled برابر 1 انجام می‌شود؛ کانال غیرفعال انتخاب نمی‌شود.
- فقط کلیدهای persian_subtitle_channels زیرنویس فارسی می‌گیرند. فهرست فعلاً خالی است و هیچ کانالی به‌صورت ضمنی فعال نیست.
- برای کانال‌های دارای زیرنویس، برنامهٔ رونویسی به قطعه‌های حداکثر 15 دقیقه‌ای تقسیم می‌شود؛ سقف پیش‌فرض 96 قطعه است.
- پیکربندی اولیهٔ Whisper مدل small و int8 CPU است؛ کیفیت و زمان اجرا باید در تست جداگانه سنجیده شوند.

## ترتیب ادامهٔ توسعه

1. این مرحله: سیاست 720p، اعتبارسنجی URL، فرمان‌های قابل‌آزمایش yt-dlp/ffmpeg و کنترل بودجهٔ دیسک/آپلود.
2. مرحلهٔ بعد: downloader واقعی، خواندن فضای دیسک در لحظه، ffprobe و تبدیل واقعی؛ هیچ صف یا انتشار فعلی درگیر نمی‌شود.
3. سپس: faster-whisper با dependency نسخه‌بندی‌شده و خروجی SRT زمان‌دار.
4. بعد: ترجمهٔ SRT از Groq با سهمیهٔ روزانهٔ مستقل YouTube، ثبت امن و fail-closed. سهمیهٔ Mob دست‌نخورده می‌ماند.
5. سپس: SRT فارسی و حک زیرنویس با فونت Vazirmatn داخل ریپو.
6. فقط پس از تأیید سقف آپلود و تست خروجی، ادغام کنترل‌شده با صف در PR مستقل.

این مرحله مایگریشن D1، Secretها، workflowهای زمان‌بندی‌شده، quiet_hours، قفل کانال اصلی یا منطق انتشار را تغییر نمی‌دهد.
