# جمع‌آوری ابری در GitHub Actions + Termux Docker

این سند مسیر فعال را توضیح می‌دهد. **Termux در این معماری داخل Docker روی runnerهای GitHub Actions اجرا می‌شود؛ اجرای فرمان روزانه روی گوشی لازم نیست.** اسکریپت‌های راه‌اندازی/اجرای دستی مخصوص گوشی حذف شده‌اند.

## گردش کار فعال

فایل اجرایی: `.github/workflows/termux-docker-discovery.yml`

- زمان‌بندی هر ساعت در دقیقه‌های ۷ و ۳۷ اجرا می‌شود؛ هر اجرا ابتدا فقط گیت زمان‌بندی را بررسی می‌کند.
- جمع‌آوری کامل زمانی ادامه پیدا می‌کند که گیت پنج‌ساعته، بر اساس آخرین چرخهٔ موفقِ intake به D1، اجازه بدهد.
- CI همهٔ تست‌های Python را قبل از کشف زنده اجرا می‌کند؛ سپس runner، تصویر `termux/termux-docker:x86_64` را بالا می‌آورد و ابزارهای لازم را داخل همان محیط نصب می‌کند.
- گزارش عمومی و metadata-only از شش پروفایل انتخاب‌شدهٔ TikTok و منبع رسمی Mob Entertainment در X ساخته می‌شود. مسیر Mob فقط X است و محدودیت `born_at` به همان مسیر خبر رسمی مربوط می‌شود، نه صف عادی TikTok.
- اجرای کشف رسانه‌ای دانلود نمی‌کند، به روبیکا پیام نمی‌فرستد و از provider هوش مصنوعی پولی استفاده نمی‌کند.
- گزارش معتبر در `artifacts/termux_discovery.json` روی `main` ذخیره می‌شود. سپس `queue_intake` حداکثر چهار URL جدید را پس از فیلترها و بررسی تکراری‌ها به صف پایدار D1 اضافه می‌کند.
- وضعیت چرخهٔ پنج‌ساعته فقط پس از موفقیت intake ثبت می‌شود. اگر هر دو مسیر کشف صفر نامزد برگردانند یا گزارش معتبر نباشد، گزارش قبلی جایگزین و چرخه موفق علامت‌گذاری نمی‌شود.

## نقش فایل‌ها

- `.github/workflows/termux-docker-discovery.yml`: زمان‌بندی، اجرای container، ذخیرهٔ گزارش، intake به صف و ثبت وضعیت موفق.
- `termux/daily_discovery.py`: collector که داخل Termux Docker اجرا می‌شود؛ نام پوشه به محیط اجرا اشاره دارد و به معنی اجرای دستی روی تلفن نیست.
- `artifacts/termux_discovery.json`: گزارش metadata. این فایل توکن یا فایل رسانه‌ای ذخیره نمی‌کند.
- `artifacts/termux_collection_state.json`: نشانگر چرخهٔ موفق برای گیت پنج‌ساعته.
- `.github/workflows/daily-queue-processor.yml`: پردازش جداگانهٔ صف؛ برخلاف collector، این مسیر می‌تواند رسانه دانلود کند و در کانال تنظیم‌شده منتشر کند. کنترل مقصد، سقف روزانه و گیت‌های انتشارش مستقل‌اند.

## بررسی اجرا و خطاها

1. در GitHub به **Actions → Online Termux discovery and queue sync** برو و آخرین اجرا را بررسی کن.
2. در Summary، نتیجهٔ گیت، تعداد نامزدها، وضعیت push گزارش و نتیجهٔ D1 intake را بخوان.
3. اگر اجرا پیش از collector متوقف شده، اول نتیجهٔ تست‌ها و دسترسی runner به Docker را بررسی کن. اگر collector نامزد صفر داده، منبع و `SOURCE_ATTEMPT`های Summary را بررسی کن.
4. اگر intake شکست خورد، به اجرای موفق فرضش نکن؛ وضعیت چرخهٔ پنج‌ساعته بعد از intake موفق ثبت می‌شود.

برای این گردش کار نیازی به نصب Termux، اجرای `termux/bootstrap.sh`، فرمان روزانه روی گوشی یا push دستی گزارش نیست. این مسیر به‌تنهایی انتشار روبیکا انجام نمی‌دهد.
