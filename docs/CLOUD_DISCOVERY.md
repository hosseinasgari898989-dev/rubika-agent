# جمع‌آوری خودکار ابری Rubika-Agent

## اصل مهم
برای اجرای زمان‌بندی‌شدهٔ پروژه نیازی به بازکردن Termux روی گوشی یا واردکردن دستور روزانه نیست. GitHub Actions میزبان اجرای ابری است و Termux درون Docker روی runner اجرا می‌شود.

## مسیر زمان‌بندی‌شده
1. گردش‌کار `.github/workflows/termux-docker-discovery.yml` در شاخهٔ `main` هر ۳۰ دقیقه موعد را بررسی می‌کند.
2. در صورت رسیدن موعد پنج‌ساعته، کد مغز را از شاخهٔ `agent-brain-mega-v1` می‌گیرد و تست‌های لازم را اجرا می‌کند.
3. پیش از جمع‌آوری، `/health` بررسی می‌شود؛ پاسخ باید سلامت Worker و اتصال D1 را تأیید کند.
4. Termux داخل Docker فقط metadata عمومی را جمع می‌کند. این مرحله ویدئو دانلود یا در روبیکا منتشر نمی‌کند.
5. گزارش اعتبارسنجی می‌شود و فقط فایل گزارش به `agent-brain-mega-v1` فرستاده می‌شود.
6. تا چهار نامزد جدید TikTok، اگر شرایط فیلتر و عدم‌تکرار را داشته باشند، در صف پایدار D1 قرار می‌گیرند.
7. نشانگر پنج‌ساعته فقط پس از موفقیت ورود اطلاعات به صف ثبت می‌شود. نامزدهای صرفاً خبری Mob نباید صف ادیت TikTok را به‌اشتباه موفق جلوه دهند.

## کدام فایل‌های Termux باید بمانند؟
`termux/daily_discovery.py` و ماژول‌های مربوط به کشف، بخشی از اجرای ابری هستند و نباید حذف شوند. اسکریپت‌های مخصوص اجرای دستی روزانه روی گوشی، مسیر ضروری پروژه نیستند و از شاخهٔ اصلی حذف شده‌اند.

## مسیر انتشار، جداست
گردش‌کار پردازش صف در `.github/workflows/daily-queue-processor.yml` مستقل از کشف است. در نسخهٔ فعلی روی کانال تست قفل شده و سقف آن یک انتشار موفق در روز است. تغییر آن به چهار ویدئو در روز و فعال‌کردن مسیر نهایی اخبار رسمی، مرحلهٔ جداگانه‌ای است؛ زمان‌بندی جمع‌آوری پنج‌ساعته نباید برای این کار حذف یا با Termux گوشی جایگزین شود.

## عیب‌یابی
- اگر `/health` پاسخ معتبر ندهد یا D1 متصل نباشد، جمع‌آوری قبل از مصرف زمان runner متوقف می‌شود.
- اگر مخزن رسمی اول Termux پاسخ ندهد، گردش‌کار mirror رسمی جایگزین را امتحان می‌کند.
- اگر TikTok نامزد معتبری پیدا نکند، اجرای آن چرخه شکست می‌خورد تا نشانگر پنج‌ساعته به‌اشتباه جلو نرود.
- گزارش‌ها و لاگ‌های همان اجرای GitHub Actions منبع اصلی بررسی هستند؛ اجرای دستی گوشی برای این جریان لازم نیست.
