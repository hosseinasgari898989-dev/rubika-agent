# دستیار خصوصی پروژه در Termux و روبیکا

## این مرحله چه می‌سازد؟

این یک دستیار جدا از زمان‌بندی اصلی GitHub Actions است. وقتی خودت در Termux دستور شروع را اجرا کنی، برنامهٔ گوشی پیام‌های ربات را بررسی می‌کند و فقط به پیام خصوصی صاحب تنظیم‌شده پاسخ می‌دهد. فرمان‌های شناخته‌شده:

- \`/start\` و \`/help\`: معرفی و راهنما
- \`/status\`: وضعیت امن، مدل انتخاب‌شده و سهمیهٔ محلی
- \`/provider groq\` یا \`/provider openrouter\`: انتخاب دستی ارائه‌دهنده
- \`/reset\`: پاک‌کردن تاریخچهٔ گفت‌وگوی همان نشست
- \`/stop\`: توقف برنامه

پیام عادی می‌تواند دربارهٔ پروژه، کد یا خطاها باشد. عامل بخش‌های مرتبط را از فایل‌های مجاز مخزن محلی و به‌صورت فقط‌خواندنی پیدا می‌کند و همراه سؤال به ارائه‌دهندهٔ انتخابی می‌فرستد. تاریخچهٔ گفت‌وگو در حافظهٔ همان نشست می‌ماند؛ فایل وضعیت تنها شناسهٔ پیمایش پیام‌ها، شمارندهٔ روزانه و ارائه‌دهندهٔ انتخابی را نگه می‌دارد.

**محدودیت این مرحله:** عامل هنوز اجازهٔ ویرایش فایل، اجرای فرمان، ساخت commit یا PR، تغییر دیتابیس، Deploy یا انتشار در روبیکا را ندارد. می‌تواند توضیح بدهد و طرح تغییر پیشنهاد کند. اجرای امن تغییرات با تأیید صریح، مرحلهٔ جداگانه است.

## تنظیمات خصوصی یک‌باره

تنظیمات و کلیدها باید بیرون از مخزن باشند. در Termux، پوشه و فایل خصوصی را بساز:

\`\`\`bash
mkdir -p ~/.config/rubika-agent
chmod 700 ~/.config/rubika-agent
nano ~/.config/rubika-agent/interactive.env
\`\`\`

این متغیرها را داخل فایل قرار بده و مقادیر واقعی را فقط در همان فایل محلی وارد کن:

\`\`\`bash
export RUBIKA_TOKEN='توکن ربات خودت'
export RUBIKA_OWNER_CHAT_ID='شناسه چت خصوصی خودت'
export INTERACTIVE_AI_PROVIDER='groq'
export GROQ_API_KEY='کلید Groq خودت'
# اختیاری؛ اگر OpenRouter را هم تنظیم کرده‌ای:
export OPENROUTER_API_KEY='کلید OpenRouter خودت'
\`\`\`

اگر مقدار را داخل فایل وارد کردی، آن را ذخیره و خارج شو؛ سپس فقط دسترسی فایل را محدود کن:

\`\`\`bash
chmod 600 ~/.config/rubika-agent/interactive.env
\`\`\`

کلیدها را در چت روبیکا، سورس کد، README، گزارش‌ها یا GitHub commit نگذار. عامل نسخهٔ اول از \`GROQ_API_KEY\` یا \`OPENROUTER_API_KEY\` که خودت محلی تنظیم کرده‌ای استفاده می‌کند؛ این نسخه از کلیدهای مخفی GitHub به‌صورت خودکار روی گوشی کپی نمی‌کند. اگر کلید هیچ ارائه‌دهنده‌ای موجود نباشد، عامل می‌تواند وضعیت و راهنما را بگوید اما پاسخ مدل تولید نمی‌کند.

## اجرا و توقف

پس از دریافت این شاخه در مخزن محلی و نصب وابستگی‌های عادی پروژه، از ریشهٔ مخزن این فرمان را اجرا کن:

\`\`\`bash
bash termux/interactive-start.sh
\`\`\`

برای توقف، \`/stop\` را در گفت‌وگوی خصوصی ربات بفرست یا در Termux کلیدهای \`Ctrl+C\` را بزن. این فرایند فقط وقتی فعال است که روی گوشی اجرا شده باشد؛ برای کارکرد مکالمه، گوشی باید روشن و به اینترنت متصل باشد. زمان‌بندی خودکار اصلی پروژه داخل GitHub Actions باقی می‌ماند و به این عامل وابسته نیست.

## حریم خصوصی، سهمیه و محدودیت‌ها

- عامل فقط به ترکیب شناسهٔ فرستنده و شناسهٔ چتِ تنظیم‌شده اجازه می‌دهد؛ پیام گروه یا کانال و پیام افراد دیگر نادیده گرفته می‌شود.
- فقط روش‌های ثابت \`getMe\`، \`getUpdates\` و \`sendMessage\` برای ربات استفاده می‌شوند. این برنامه هیچ پستی به کانال ارسال نمی‌کند.
- فهرست فایل‌های قابل بررسی به کد و مستندات مجاز محدود است؛ \`config/\`، \`artifacts/\`، فایل‌های محیطی و پوشهٔ Git خوانده نمی‌شوند. متن‌های شبیه کلید نیز پیش از ساخت متن زمینه پاک‌سازی می‌شوند.
- حداکثر ۲۰ تلاش مدل در هر روز UTC در وضعیت محلی ثبت می‌شود. این سقف جای سهمیهٔ ارائه‌دهنده را نمی‌گیرد و رایگان‌بودن یا دسترسی همیشگی هیچ ارائه‌دهنده‌ای تضمین‌شده نیست.
- اگر نتیجهٔ تماس مدل نامشخص یا محدودشده باشد، همان پیام به‌صورت خودکار به ارائه‌دهندهٔ دیگری فرستاده نمی‌شود؛ این کار از دوباره‌فرستادن ناخواستهٔ سؤال جلوگیری می‌کند.
- **متن سؤال و بخش‌های مرتبط از فایل‌های محلی به سرویس ابری مدل انتخاب‌شده فرستاده می‌شود.** اطلاعات شخصی، توکن، کلید، رمز و داده‌ای را که اجازهٔ اشتراک‌گذاری‌اش را نداری وارد چت نکن.
- پردازش متن مدل روی سرور Groq یا OpenRouter انجام می‌شود، نه با CPU گوشی. گوشی مسئول اتصال روبیکا، انتخاب زمینهٔ محلی و مدیریت نشست است.
- CI فقط آزمون‌های آفلاین را اجرا می‌کند؛ این مرحله عمداً پیام روبیکا یا درخواست زندهٔ مدل ارسال نمی‌کند.
