# دستیار خصوصی Rubika-Agent با هوش مصنوعی محلی در Termux

## هدف این نسخه

دستیار فقط وقتی اجرا می‌شود که خودت آن را در Termux گوشی روشن کنی. متن مدل با llama.cpp و یک فایل مدل GGUF روی همان گوشی پردازش می‌شود. هیچ کلید یا API هوش مصنوعی از Groq، OpenRouter یا سرویس مشابه لازم نیست.

برای گرفتن و فرستادن پیام، ربات همچنان به اینترنت و API روبیکا نیاز دارد. اما متن سؤال و بخش‌های انتخاب‌شده از فایل‌های پروژه به یک سرور محلی با نشانی ثابت 127.0.0.1 فرستاده می‌شود؛ این برنامه آن‌ها را برای استنتاج به یک سرویس ابری هوش مصنوعی نمی‌فرستد.

این دستیار فقط راهنمایی می‌کند: فایل را ویرایش نمی‌کند، فرمان دلخواه اجرا نمی‌کند، PR نمی‌سازد، Deploy نمی‌کند، دیتابیس را تغییر نمی‌دهد و در کانال پست نمی‌گذارد. زمان‌بندی GitHub Actions مستقل می‌ماند.

## ۱. نصب پیش‌نیازها

در Termux اجرا کن:

~~~bash
pkg update
pkg install -y git python curl nano llama-cpp
~~~

سپس این نسخه را در یک پوشهٔ تازه دریافت کن؛ پوشه‌ها و فایل‌های پروژهٔ قبلی‌ات تغییر نمی‌کنند:

~~~bash
git clone --depth 1 --branch feature/termux-private-ai-agent-stage4 https://github.com/hosseinasgari898989-dev/rubika-agent.git ~/rubika-agent-stage4-local
cd ~/rubika-agent-stage4-local
python -m pip install 'requests>=2.31,<3'
~~~

اگر شاخهٔ اصلاح‌شده هنوز روی GitHub منتشر نشده باشد، تا آماده‌شدن آن، این فرمان clone را اجرا نکن.

## ۲. دریافت مدل محلی

مدل سبک Qwen2.5-0.5B-Instruct در قالب GGUF حدود 400 مگابایت حجم دارد. پاسخ‌های فارسی آن برای پروژه‌های پیچیده ممکن است محدود باشد، اما برای بررسی اولیهٔ اجرای محلی مناسب است.

~~~bash
mkdir -p ~/models
cd ~/models
curl -L --fail --retry 2 -o qwen2.5-0.5b-instruct-q4_k_m.gguf https://huggingface.co/bartowski/Qwen2.5-0.5B-Instruct-GGUF/resolve/main/Qwen2.5-0.5B-Instruct-Q4_K_M.gguf
~~~

دانلود مدل به اینترنت و فضای آزاد نیاز دارد. پس از دانلود، خود استنتاج مدل بدون API و روی گوشی انجام می‌شود.

## ۳. روشن‌کردن موتور مدل

این دستور را در یک نشست Termux جدا اجرا کن و بگذار باز بماند:

~~~bash
llama-server -m "$HOME/models/qwen2.5-0.5b-instruct-q4_k_m.gguf" --host 127.0.0.1 --port 8080 --ctx-size 2048 --alias qwen-local --threads 4
~~~

اگر فرمان پیدا نشد، خطای کمبود حافظه دیدی، یا سرور اجرا نشد، هنوز سراغ راه‌اندازی ربات نرو. خروجی خطا را بررسی کن. مدل فقط روی 127.0.0.1 گوش می‌دهد و به شبکهٔ عمومی باز نمی‌شود.

## ۴. بررسی مستقل مدل

در نشست Termux دیگری:

~~~bash
cd ~/rubika-agent-stage4-local
python -m termux.interactive_agent --check-local-model
~~~

پاسخ موفق شبیه این است:

~~~json
{"endpoint":"127.0.0.1:8080","inference":"local_llama_cpp","ok":true}
~~~

برای تست مستقیم پاسخ مدل:

~~~bash
curl -sS http://127.0.0.1:8080/v1/chat/completions -H 'Content-Type: application/json' -d '{"model":"qwen-local","messages":[{"role":"user","content":"به فارسی فقط بگو مدل محلی آماده است."}],"max_tokens":80,"stream":false}
~~~

اگر فرمان بررسی موفق نیست، مدل/سرور آماده نیست و باید همان مشکل را قبل از آزمایش روبیکا حل کرد.

## ۵. تنظیم محرمانهٔ ربات

فایل تنظیمات بیرون از مخزن ذخیره می‌شود:

~~~bash
mkdir -p ~/.config/rubika-agent
chmod 700 ~/.config/rubika-agent
nano ~/.config/rubika-agent/interactive.env
~~~

فعلاً این دو خط را با اطلاعات واقعی ربات خودت جایگزین کن:

~~~bash
export RUBIKA_TOKEN='توکن ربات خودت'
export LOCAL_MODEL_NAME='qwen-local'
~~~

توکن را فقط داخل همین فایل محلی وارد کن، ذخیره کن و سپس اجرا کن:

~~~bash
chmod 600 ~/.config/rubika-agent/interactive.env
set -a
source ~/.config/rubika-agent/interactive.env
set +a
cd ~/rubika-agent-stage4-local
python -m termux.interactive_agent --check-rubika
~~~

اگر نتیجه شامل "rubika_api":"connected" بود، توکن و ارتباط API روبیکا تأیید شده است. این بررسی پیامی نمی‌فرستد.

## ۶. پیدا کردن شناسهٔ چت و فرستنده

در روبیکا وارد گفت‌وگوی خصوصی ربات خودت شو و یک پیام مثل /start برایش بفرست. سپس در Termux اجرا کن:

~~~bash
python -m termux.interactive_agent --discover-owner-ids
~~~

این دستور فقط شناسهٔ چت و شناسهٔ فرستندهٔ پیام‌های خصوصی را چاپ می‌کند، نه متن پیام و نه توکن را. مقادیر نمایش‌داده‌شده را در فایل تنظیمات، به دو خط زیر اضافه کن:

~~~bash
export RUBIKA_OWNER_CHAT_ID='شناسهٔ chat_id که دستور نشان داد'
export RUBIKA_OWNER_USER_ID='شناسهٔ sender_id که دستور نشان داد'
~~~

اگر شناسه‌ها برابر بودند، می‌توانی همان مقدار را در هر دو خط بگذاری. اگر دستور پیامی پیدا نکرد، دوباره در گفت‌وگوی خصوصی ربات پیام بفرست و دستور کشف شناسه را تکرار کن. هیچ‌کدام از شناسه‌ها یا توکن را در این گفت‌وگو برای من ارسال نکن.

بعد فایل را ذخیره کن و مجوز آن را دوباره محدود کن:

~~~bash
chmod 600 ~/.config/rubika-agent/interactive.env
~~~

## ۷. آزمایش خود ربات

موتور llama-server باید در نشست اول باز بماند. در نشست دوم، از ریشهٔ مخزن اجرا کن:

~~~bash
cd ~/rubika-agent-stage4-local
bash termux/interactive-start.sh
~~~

در گفت‌وگوی خصوصی ربات، این فرمان‌ها را یکی‌یکی بفرست:

- /start — معرفی و اطلاعات حریم خصوصی
- /status — وضعیت و شمارندهٔ محلی
- سلام، پروژه چه کاری انجام می‌دهد؟ — آزمایش پاسخ واقعی مدل محلی
- /help — راهنما
- /stop — توقف برنامه

برای پایان‌دادن به پردازش نیز می‌توانی در Termux کلیدهای Ctrl+C را بزنی. برای کارکرد دستیار باید گوشی روشن و به اینترنت متصل باشد.

## حریم خصوصی و محدودیت‌ها

- فقط پیام خصوصیِ شناسهٔ چت و فرستنده‌ای که خودت تنظیم کرده‌ای پذیرفته می‌شود.
- فقط روش‌های ثابت getMe، getUpdates و sendMessage برای ربات فراخوانی می‌شوند؛ هیچ پست کانالی منتشر نمی‌شود.
- بخش‌های مجاز مخزن فقط‌خواندنی هستند؛ تنظیمات، داده‌ها، آثار خروجی و پوشهٔ Git خوانده نمی‌شوند.
- حداکثر ۲۰ تلاش برای پاسخ مدل در هر روز UTC ثبت می‌شود. اگر موتور محلی در دسترس نباشد، شمارنده مصرف نمی‌شود. درخواست نامشخص به‌صورت خودکار دوباره ارسال نمی‌شود.
- مدل انتخابی کوچک است و ممکن است پاسخ ضعیف یا نادرست بدهد؛ پاسخ مهم را خودت بررسی کن.
- CI فقط آزمون‌های آفلاین را اجرا می‌کند. کلید واقعی، پیام واقعی روبیکا یا درخواست زندهٔ مدل در CI آزمایش نمی‌شود.
- این دستیارِ Termux مستقل از زمان‌بندی اصلی GitHub Actions است. راه‌اندازی یا متوقف‌کردن آن برنامهٔ انتشار زمان‌بندی‌شده را تغییر نمی‌دهد.
